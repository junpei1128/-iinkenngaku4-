# サーバー設定ガイド

## 環境変数の設定

1. `server/env.template` を `server/.env` にコピーします：

```bash
cp env.template .env
```

2. `.env` ファイルを編集し、以下の値を設定します：

### 必須設定

- **GMAIL_USER**: Gmailアドレス
  - 例: `your-email@gmail.com`
  - このアドレスからメールが送信されます

- **GMAIL_APP_PASSWORD**: Gmailアプリパスワード（16文字）
  - 取得方法:
    1. Googleアカウントにログイン: https://myaccount.google.com/
    2. **セキュリティ** をクリック
    3. **2段階認証プロセス** が有効になっていることを確認（無効の場合は有効化）
    4. **アプリパスワード** をクリック（2段階認証を有効にした後に表示されます）
    5. **アプリを選択** → **その他（カスタム名）** を選択し、名前を入力（例: `医院見学レポートシステム`）
    6. **生成** をクリック
    7. 表示された16文字のパスワードをコピー（この画面でしか表示されません）
    8. `.env` ファイルの `GMAIL_APP_PASSWORD` に貼り付け

### オプション設定

- **PORT**: サーバーのポート番号（デフォルト: 3001）
- **FRONTEND_URL**: フロントエンドのURL（CORS設定用、デフォルト: http://localhost:5185）

## サーバーの起動

```bash
npm run dev
```

環境変数が正しく設定されていれば、警告メッセージは表示されません。

## トラブルシューティング

### 警告: GMAIL_USERまたはGMAIL_APP_PASSWORDが設定されていません

`.env` ファイルが正しく作成され、Gmailの認証情報が設定されているか確認してください。

### メール送信エラー

1. **アプリパスワードが正しいか確認**
   - 16文字の文字列が正しく設定されているか
   - 通常のGmailパスワードではなく、アプリパスワードを使用しているか

2. **2段階認証が有効か確認**
   - アプリパスワードを使用するには、2段階認証が必須です

3. **サーバーログでエラーメッセージを確認**
   - エラーの詳細を確認し、問題を特定

4. **Gmailの送信制限を確認**
   - 個人アカウント: 1日500通まで
   - 制限に達した場合は、翌日まで待つ必要があります

### よくあるエラー

- **"Invalid login"**: アプリパスワードが間違っている、または通常のパスワードを使用している
- **"Less secure app access"**: 2段階認証が有効になっていない
- **"Daily sending quota exceeded"**: 1日の送信制限に達した
